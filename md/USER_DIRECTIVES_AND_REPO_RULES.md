# 사용자 지시사항 및 레포 작업 규칙

이 문서는 이번 대화에서 사용자가 `implantsj` 레포에 대해 직접 지시한 작업 원칙과 우선순위를 정리한 문서다.

## 1. 가장 중요한 현재 목표

현재 1순위 목표는 다음이다.

> 기존 metric learning / ViT / VLM 코드 구조를 최대한 재사용해서, 폐쇄망 Ubuntu 환경에서 최소한의 타이핑으로 전체 데이터에 13feature를 추가하는 것

`unseen15` class 학습은 현재 우선순위가 아니다. 로컬 VLM 기반 13feature 추가를 먼저 진행한다.

## 2. 환경 제약

사용자가 명시한 환경 제약은 아래와 같다.

- 현재 작업 환경은 폐쇄망 Ubuntu다.
- 코드를 복사하거나 붙여넣을 수 없다.
- 긴 코드를 새로 작성하기 어렵다.
- 새 코드를 처음부터 많이 쓰지 말고 기존 코드 구조를 최대한 재사용해야 한다.

## 3. 코드 작성 및 수정 원칙

사용자가 명시적으로 지시한 원칙:

1. 기존 파일 구조와 기존 코드를 먼저 확인할 것
2. 새 파일을 길게 만들기보다 기존 코드에서 최소 지점만 수정할 것
3. 직접 타이핑해야 하는 코드는 최대한 짧게 작성할 것
4. 가능하면 한 줄 명령어 또는 몇 줄 이내 수정으로 해결할 것
5. 기존 함수, Dataset, Model, transform, checkpoint loading, evaluation 로직을 최대한 재사용할 것
6. 이미 구현된 코드와 중복되는 코드는 새로 작성하지 말 것
7. 원본 파일을 건드리지 않고 별도 test script나 wrapper script로 해결하는 방식을 우선 제안할 것

## 4. 승인 없는 수정 금지 원칙

사용자가 명시적으로 금지한 사항:

- 기존 코드 파일을 임의로 수정하지 말 것
- 사용자 허락 없이 기존 파일에 직접 patch / overwrite / replace / edit 하지 말 것
- 먼저 현재 코드 구조를 분석한 뒤, 수정이 필요한 부분만 설명할 것
- 수정이 필요하면 최종 수정본 전체를 먼저 보여준 뒤 승인을 받을 것
- 사용자가 `수정해도 된다`, `적용해라`라고 허락한 뒤에만 실제 파일 수정을 진행할 것
- 기존 파일을 수정해야 한다면 수정 전 백업 명령어도 함께 제시할 것

## 5. 응답 형식 요구사항

사용자는 다음 형식으로 답변할 것을 요구했다.

1. 현재 코드 구조에서 재사용할 수 있는 부분
2. 수정이 필요한 최소 지점
3. 직접 타이핑해야 하는 최소 명령어
4. 수정 전 백업 명령어
5. 최종 수정본 또는 추가할 코드
6. 실제 적용 여부 확인 질문

## 6. unseen15 결과 해석 관련 사용자 요구사항

사용자는 unseen15 metric 결과가 낮게 나온 이유에 대해 아래 취지로 정리해달라고 요청했다.

- 27 seen class로 학습한 metric space는 15 unseen class를 구분하도록 직접 학습된 것이 아님
- 현재 구조는 CLIP 같은 진짜 zero-shot 구조가 아님
- unseen prototype 품질 및 데이터 부족 문제 가능성이 큼
- 이 실험은 unseen class 정확 분류보다 seen embedding space에서 어디로 매핑되는지 분석하는 실험으로 해석하는 것이 맞음

이 내용은 별도 문서 `UNSEEN15_METRIC_RESULT_INTERPRETATION.md`에 정리했다.

## 7. local_qwen 관련 사용자 지시사항

사용자는 아래 사항도 직접 지시했다.

- `run_local_qwen`은 현재 폐쇄망에 없는 파일이라고 명시함
- 따라서 로컬 저장소에서도 관련 파일을 삭제하라고 지시함

현재 반영 상태:

- `run_local_qwen_vlm.py` 제거
- 관련 `local_qwen` 테스트 파일 제거
- `local_qwen` 관련 잔여 파일 검색 확인

## 8. 문서화 요구사항

사용자는 다음 요구를 명시했다.

- 이번 대화에서 지시한 사항들을 해당 레포 안에 문서화할 것
- `md` 폴더를 생성하고 그 안에 정리할 것
- 단순 분석 문서만이 아니라 사용자가 지시한 작업 원칙 자체도 문서로 남길 것

이 문서는 그 요구를 직접 반영한 문서다.

## 9. 현재 작업에 대한 실무 해석

지금 이 레포에서 따라야 할 실무 원칙은 아래처럼 요약된다.

1. 먼저 기존 코드 구조를 최대한 읽고 재사용한다.
2. 긴 신규 구현보다 기존 코드 조합을 우선한다.
3. 승인 없는 원본 수정은 금지한다.
4. 가능하면 짧은 명령어, 짧은 wrapper, 짧은 수정으로 해결한다.
5. 현재 최우선 목표는 전체 데이터 13feature 추가다.
6. `unseen15` 성능 평가는 분류 자체보다 mapping 분석으로 해석한다.

## 10. Mac 로컬과 폐쇄망의 연결 제약

- Mac 로컬 환경과 폐쇄망 Ubuntu 서버 사이에는 연결 경로가 없다.
- 폐쇄망에서 접근 가능한 작업 경로는 `/workspace/data`, `/workspace/implantsj`, `/workspace/outputs`이다.
- `/workspace/implantsj_seg`는 접근하거나 중단하지 않는다.
- 로컬 파일, 로컬 클립보드, SSH/SCP, Git push/pull 또는 RDP 클립보드로 코드를 전달할 수 있다고 가정하지 않는다.
- 폐쇄망 작업은 Windows App 안의 Ubuntu/VS Code에서 직접 입력하고 실행한다.
- Windows App 내부 단축키는 Windows 기준(`Ctrl` 계열)으로 사용한다. 이때 `Ctrl`은 MacBook의 물리 `control` 키이며, `command` 키는 사용하지 않는다.
- Codex가 입력할 수 없는 문자나 명령만 사용자에게 정확히 요청한다.
- 로컬에서 만든 파일을 폐쇄망으로 옮기려는 우회 전송을 다시 시도하지 않는다.

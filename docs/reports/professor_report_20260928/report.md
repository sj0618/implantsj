# 임플란트 인식 실험 보고 — 2026-09-28

> 작성 중: 서버 metric 캐시 40개, 백본 캐시 20개, GT 및 대응 query의 거리 표를 반영했다. M1/M6 연결 확인, 최근 41클래스의 Seen/Unseen 분리, 최신 정확도 원본 대조가 남아 있다. 로컬 임베딩은 분석에서 제외했다.

## 1. 교수님께 설명할 핵심

임플란트 X-ray를 벡터(임베딩)로 바꾼 뒤, 등록된 임플란트 종류별 대표 벡터(프로토타입)와 거리를 비교해 종류를 찾는 실험이다. 학습에 사용한 종류(Seen)뿐 아니라, 모델 학습에 사용하지 않은 종류(Unseen)도 등록용 이미지로 대표 벡터를 만들면 구분할 수 있는지 확인했다.

실험은 이미지 전용 모델 → 속성 점수 결합 → 이미지 패치와 속성 토큰 결합 → 별도 모델이 예측한 속성 확률 결합 → 고품질 GT X-ray로 프로토타입 교체 순서로 진행했다. 현재 기록에서는 속성을 넣었다고 Unseen 성능이 개선되지는 않았다. GT 프로토타입 평가도 낮은 정확도를 보였지만, 추출 경로·전처리·매핑 검증 전에는 고품질 GT 자체가 나쁘다고 결론 내릴 수 없다.

## 3. 속성 결합 방식

사용한 8개 속성: `System`, `Connection_1`, `Flange`, `Collar`, `Microthread`, `Body_Shape`, `Thread_Shape`, `Apex_Shape`.

| 실험 | 모델 입력과 학습 | 확인하고 싶은 질문 |
|---|---|---|
| 이미지 전용 | 이미지 → DINOv2 → 임베딩, SupCon 학습 | 이미지 특징만으로 어디까지 가능한가 |
| 속성 점수 결합 | 이미지 거리 점수 + 속성별 예측 확률 점수 | 속성이 최종 판정을 보완하는가 |
| 학습 가능한 속성 토큰 | 256개 이미지 패치 + CLS + 속성 토큰 8개, SupCon + 속성 보조 CE | 속성을 함께 예측하면 이미지 표현이 좋아지는가 |
| 예측 속성 토큰 | 고정 ConvNeXt-Tiny의 속성 확률 → 속성별 선형 투영 → 토큰에 추가 | 이미지별 속성 예측을 모델 내부에서 활용하면 좋아지는가 |
| GT mean 프로토타입 | 클래스별 GT 이미지 전체 임베딩의 산술평균으로 대표 벡터 생성 | 고품질 등록 이미지가 분류에 도움이 되는가 |

예측 속성 토큰 모델은 학습·검증·테스트 모두 예측 확률을 입력한다. 정답 속성은 보조 손실 target에만 사용한다. 고정 속성 모델에는 역전파하지 않으며, 융합 모델의 속성 헤드에 보조 손실을 적용한다. 정답 속성을 test 입력에 넣은 oracle 실험으로 해석하면 안 된다.

224×224는 입력 크기, 14×14는 DINOv2 패치 크기이며 이미지 패치는 256개다. 기존 속성 토큰 실험은 이미지마다 정답 속성을 넣은 구조가 아니라 학습 가능한 토큰을 추가한 구조였다.

## 5. Unseen 성능이 낮아진 이유를 어떻게 설명할까

**근거가 있는 가설:** 별도 속성 모델이 Unseen에서 일부 속성을 잘못 예측하면, 융합 모델도 그 오류를 입력으로 받는다. 기존 속성 모델의 Unseen 정확도는 Body_Shape 25.7%, Apex_Shape 28.7%, Microthread 48.4%였다. 모델이 Seen의 익숙한 속성 조합을 강하게 예측하는지, 임베딩 분리가 실제로 줄었는지 확인해야 한다.

## 6. 임베딩 거리 측정 기준

- 여기서 클러스터는 **정답 클래스별 샘플 집합**이다. Kmeans 내부의 하위 군집과 구분한다.
- 모델별 벡터 크기 차이를 제거하기 위해 각 샘플을 L2 정규화한다. 원래 평균 norm도 별도 기록한다.
- **클래스 내부 거리:** 같은 클래스의 서로 다른 모든 샘플 쌍(i<j)의 거리 평균. 클래스별 평균을 다시 동일 가중치로 평균한다. 샘플 1개인 클래스는 쌍이 없으므로 제외하고 별도 표시한다.
- **클래스 간 거리:** 클래스별 정규화 샘플 평균(중심)을 구하고, 서로 다른 모든 중심 쌍의 거리 평균.
- **분리 비율:** 클래스 간 평균 거리 / 클래스 내부 평균 거리. 동일 데이터·거리 정의에서 클수록 분리되는 경향이 있지만, 정확도를 보장하지 않는다.
- Euclidean과 cosine distance(1−cosine similarity)를 각각 계산한다. cosine similarity와 distance를 뒤섞지 않는다.
- test 정답은 사후 분석용 군집 구분에만 사용한다. 이 중심을 실제 분류기의 프로토타입으로 사용해 정확도를 높이는 실험이 아니다.
- 같은 임베딩을 쓰는 mean·medoid·Kmeans·공분산 조합은 위 클래스 구조 수치가 같다. 분류기 변경과 임베딩 학습 변경을 구분한다.

### 표를 읽는 방법

- 내부 거리가 작으면 같은 종류의 이미지들이 가깝게 모여 있다. 클래스 간 거리가 크면 종류별 중심이 멀리 떨어져 있다.
- 두 값이 함께 커질 수 있으므로 분리 비율도 본다. 예측 속성 모델은 이미지 전용 모델보다 전체 41클래스 중심 간 cosine 거리가 크지만, 내부 거리도 더 크게 증가해 분리 비율은 낮아졌다.
- 분리 비율은 정확도가 아니다. 모든 클래스 중심의 평균 거리에는 서로 구분하기 쉬운 클래스 쌍도 포함되므로, 혼동이 많은 가까운 클래스 쌍의 문제를 가릴 수 있다.
- GT 표와 query 표는 각 데이터 안의 구조다. GT 중심이 같은 클래스의 query와 가까운지는 이 두 표만으로 알 수 없다.

교수님께는 “속성 추가 후 클래스 간 거리는 늘었지만 같은 클래스 안의 산포도 커졌습니다. 전체 41클래스의 cosine 분리 비율은 이미지 전용 5.70에서 예측 속성 4.51로 낮아졌습니다. 다만 Unseen만 분리한 비교가 남아 있어 Unseen 하락 원인으로 단정하지는 않았습니다”라고 설명할 수 있다.

### 전체 평가 포함 여부 점검

사용자 지시에 따라 로컬 few-shot·PCA 임베딩은 제외하고, 서버에서 수행한 평가만 분석한다.
